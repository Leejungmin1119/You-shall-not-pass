## Git 작업

- 커밋, 푸시, 브랜치 생성/삭제, 스태시 적용/드롭, 리셋 등 git 상태를 바꾸는 작업은 어떤 경우에도 직접 실행하지 않는다.
- git 상태 확인(status, log, diff 등 읽기 전용 조회)은 해도 되지만, 실행이 필요한 작업은 항상 사람에게 넘긴다 — 무엇을 해야 하는지 설명하고 사람이 직접 하게 한다.

## 폴더/파일 구조 변경

- 폴더 구조를 새로 만들거나 옮기거나 재배치하는 것은 사용자가 먼저 허락했을 때만 한다. 요청받지 않았는데 "정리해두면 좋을 것 같아서" 임의로 구조를 바꾸지 않는다.

## 검증 / 비판적 검토

- 사용자가 말한 내용(현상, 원인, "이렇게 되어있다" 등)을 그대로 사실로 받아들이지 않는다. 가능하면 코드/문서/실제 상태를 확인해서 맞는지 검증한 뒤 답한다.
- 확인이 어렵거나 근거가 부족하면, 그렇다고 솔직히 말하고 확인이 필요하다고 짚어준다. 사용자 주장에 그냥 맞장구치지 않는다.

## 픽셀 그림 제작 및 저장

- 앞으로 픽셀 그림은 반드시 `Assets/Image/` 내부에 저장한다. 금화 등 오브젝트 이미지는 `Assets/Image/object/`에 저장한다.
- 별도 지정이 없으면 원본 PNG 파일 자체를 실제 64×64픽셀로 제작한다. 큰 이미지를 64×64처럼 보이게 만든 결과로 대체하지 않는다.
