> **기획서의 네트워크 요구사항 전체가 완료된 상태는 아니다.** 현재 완료 범위는 Mirror/LAN 기반의 레이스 상태 동기화, 서버의 구매·사용·득점 판정, 비공개 인벤토리, 기존 창 기능의 네트워크 연결이다. 폭탄·미사일은 확장 인터페이스만 있고, 현재 구매 목록에서는 비활성화되어 있다. 라운드별 맵 변화와 공개 인터넷 접속은 아직 완료되지 않았다.

## 1. 기획 해석과 범위

최신 2·3장은 공격자 한 명과 수비자 세 명의 역할 교대 방식에서 **4명이 동시에 달리면서 함정을 사용하는 개인전 레이스**로 변경되어 있다. 1·6·7장에 남아 있는 이전 역할 설명은 최신 규칙으로 간주하지 않았다. 기존 `rolechangeManager`는 레이스 세션이 있는 씬에서 우회하며, 연습 씬은 유지한다.

이번 구현은 서버 권한과 데이터 동기화를 중심으로 한다. 새 함정의 게임 동작, 그림·효과음, 인벤토리 화면과 결과 화면을 제작한 작업은 아니다. 문서의 파란색 의견, `[제안]`, `[미정]`은 팀 확정 요구사항과 구분한다. 첨부되지 않은 10장과 개별 함정·캐릭터·UI 상세 하위 페이지의 내용까지 구현했다고 간주하지 않는다.

## 2. 구현 및 검증한 네트워크 기능

| 영역 | 현재 동작 | 관련 코드 |
| --- | --- | --- |
| 로비·접속 | 기존 Mirror/KCP LAN 방 생성·검색·참가와 준비 후 씬 전환을 유지한다. 4인 접속을 같은 컴퓨터의 별도 프로세스로 확인했다. | `CapstoneRoomManager`, `LanRoomConnector` |
| 레이스 상태·시간 | Host가 Waiting, RoundReady, Racing, FinishCountdown, RoundEnd, MatchEnd와 라운드 번호를 정한다. 절대 종료 시각을 보내 각 Client가 남은 시간을 계산한다. | `RaceSession` |
| 골인·점수·승자 | Host가 골인 접촉 위치와 중복 요청을 확인한다. 순위 4/3/2/1점, 함정 적중 +1점, 자기 피격 무득점, 20점 도달 종료와 시간 종료 시 공동 우승을 처리한다. | `GoalZone`, `PlayerScore`, `RaceSession` |
| 이동·복귀 상태 | 기존 소유자 이동과 NetworkTransform 보간을 유지한다. 생존·골인 상태, 복귀 위치와 무적 종료 시각을 동기화한다. | `NetworkPlayerController`, `PlayerState` |
| 코스트·공유 컨베이어 | Host가 코스트 지급·상한, 아이템 유형·가중치·생성 시각·수명, 구매 시 제거를 관리한다. 먼저 도착한 구매 요청 하나만 성공한다. | `PlayerCost`, `ConveyorController` |
| 비공개 인벤토리 | 내용·선택 슬롯은 소유자에게만 보낸다. 다른 Client에는 보유 개수만 공개한다. 권한을 가진 Host는 전체 내용을 알 수 있다. | `NetworkRaceInventory`, `PlayerState` |
| 구매·선택·사용 | 좌클릭 구매, 우클릭 구매 후 손에 들기, 슬롯 선택·취소, 필드 사용을 서버 요청으로 연결한다. 실패한 사용은 아이템을 소모하지 않는다. | `NetworkRaceInventory`, `ConveyorItem`, `SpearDropper` |
| 요청 검증 | 이전 라운드, 비활성 상태, 잔액·빈 슬롯 부족, 손에 든 상태, 쿨타임, 만료 아이템, NaN·필드 밖 좌표, 복귀 보호 구역을 검사한다. | `NetworkRaceInventory`, `RaceSession` |
| 기존 창 연동 | 단일·2개·3개 창을 서버가 승인한다. 소유자·아이템·라운드 식별자를 보내고, 적중 결과·득점·복귀·수명 종료·라운드 정리를 동기화한다. 여러 다른 피해자를 처리하되 중복 득점은 막는다. | `RaceTrapService`, `Spear` |
| 접속 종료 | 비방장 참가자 이탈 시 현재 경기를 승자 없이 종료하는 임시 정책을 적용했다. 실제 Client 프로세스 종료 후 KCP 타임아웃을 확인했다. | `CapstoneRoomManager`, `RaceSession` |

이 표의 완료는 해당 데이터와 판정 경로에 대한 것이다. 새 HUD·카메라 연출·결과 화면까지 완성되었다는 뜻은 아니다.

## 3. 기반만 있고 실제 연동이 남은 기능

`RaceTrapService`에 활성 함정 스냅샷, 생성·제거, 소유자 ID, 수명, 서버 적중 판정의 공통 틀을 마련했다. `IRaceTrapAdapter.Supports/Create`는 개별 함정 연결 지점이다. 이동형 함정은 `ServerMove`로 위치를 갱신하고 `TrapUpdated`를 받아 표시를 연결할 수 있다.

하지만 이 인터페이스 자체가 폭탄·미사일 구현 완료를 의미하지 않는다. 폭탄·미사일 어댑터와 실제 게임 동작은 없고, 해당 항목은 `RaceNetworkRules.asset`에서 비활성화되어 있다. 연결되지 않은 아이템은 추첨에서 제외하고 사용 요청도 소모 없이 거절한다. 기존 연습용 폭탄은 이 레이스용 폭탄으로 간주하지 않는다.

## 4. 남은 네트워크 작업과 완료 기준

| 우선순위 | 작업 | 완료로 인정할 조건 |
| --- | --- | --- |
| 1 | 폭탄 실제 연동 | 서버가 구매한 아이템·좌표·소유자를 검증한 뒤 생성한다. 낙하·접촉/폭발 시점·피해 대상·득점·제거가 Host와 Client에 동일하게 반영된다. 성공 후에만 구매 목록을 활성화한다. |
| 1 | 미사일 실제 연동 | 서버가 생성·대상·추적 상태·위치·수명·적중·제거를 관리한다. Client는 받은 상태를 표시하고 서버 결과로만 득점한다. 끊김·중복 적중·대상 부재를 검사한다. |
| 2 | 라운드별 맵 변화 동기화 | Host가 다음 라운드의 맵 버전·시드 또는 변화 파라미터를 결정하고 전원에게 전달한다. 같은 지형을 준비한 뒤 출발하며, 플레이어·복귀 영역·함정 정리가 새 맵과 일치한다. 구체적인 맵 생성 방식은 게임플레이 담당과 확정해야 한다. |
| 3 | 공개 인터넷 연결 완성 | 중계 서버를 배포하고 실제 WSS 주소를 설정한 새 빌드를 만든다. 서로 다른 네트워크에서 방 생성·참가·데이터 전달·시작 후 입장 제한·접속 종료를 확인한다. 현재 Relay URL은 비어 있다. |
| 별도 검증 | 실제 다중 기기·망 품질 | 4대 기기 LAN, 서로 다른 인터넷, 지연·손실 환경에서 복제 불일치·응답 지연·정상 종료를 확인한다. 현재 같은 컴퓨터에서 프로세스를 분리한 검증과 구분한다. |

서버 이동 부정행위 검증, 지연 보정 rewind, 호스트 승계와 자동 재접속은 이번 구현에 없다. 소유자 이동은 제공된 네트워크 명세의 방향을 유지했고, 호스트 이전은 기획서에서도 범위 밖으로 표기되어 있다.

## 5. 게임플레이·UI와 함께 연결해야 하는 사항

- 고정된 구덩이별 복귀 위치: 위치 전송은 있으나 현재는 기존 SafeZone 탐색과 시작점 예비 위치를 사용한다. 기획서의 구덩이마다 고정된 복귀 위치와 최종 후퇴 거리는 추가 작업이 필요하다.
- 피격 연출과 조작 잠금: 현재 적중 후 복귀·무적 동기화가 있으며, 별도의 피격 애니메이션·연출 대기 상태를 완성한 것은 아니다.
- 인벤토리·조준·관전·결과 화면: 상태 조회와 요청/결과 이벤트는 제공하지만 새 화면 표시와 카메라 동작은 제작하지 않았다.
- 라운드별 맵 난이도: 현재는 라운드 번호만 증가한다. 지형 변화 자체와 그 네트워크 연결이 모두 남아 있다.

## 7. 검증 기록과 한계

2026-10-16에 Unity 6000.3.24f1로 다음을 확인했다.

1. Unity 컴파일과 macOS Development 빌드 성공. 패키지 셰이더 경고, 선택적 Runtime Pipeline 설정 부재, Unity Services 심볼 업로드 경고는 나타날 수 있다.
2. Editor Host + 별도 Client에서 `PurchaseChecks`, `UseAndHitChecks`, `RoundChecks`의 서버 검사 36개 통과.
3. Editor Host + 별도 macOS Client 3개, 총 4인 접속·준비·레이스 진입 확인. Client의 실제 구매/장착/사용 요청에서 성공 TargetRpc 2회와 함정 복제를 확인했다.
4. Client 3개 각각 자기 슬롯만 수신하고, 다른 플레이어는 보유 개수만 수신하는 것을 JSON 스냅샷으로 확인했다.
5. 4명의 골인 순위 점수 4/3/2/1, 라운드 종료 시 함정 정리, 인벤토리 포화·잔액 부족·구매 쿨타임 거절을 확인했다.
6. 20점 도달 시 종료와 승자 ID 전달을 확인했다. 시간 종료·4인 공동 우승은 종료 시각을 시험용으로 만료시킨 fixture로 검증했으며, 실제 15분 경기를 기다린 테스트는 아니다.
7. 별도의 Racing fixture에서 Client 프로세스를 종료하고 실제 KCP 타임아웃 뒤 승자 없는 `PlayerDisconnected` 결과가 남은 Client에 전달되는 것을 확인했다.
8. 마지막 4인 실행에서 Client 3개 로그의 게임 예외와 현재 Editor 콘솔 오류는 0개였다. 시험 실행을 모두 종료하고 LobbyScene 편집 상태로 복귀했다.

위 결과는 같은 Mac의 여러 프로세스에서 얻은 것이다. 서로 다른 기기·공유기·인터넷 접속, 장시간 반복 경기, 지연·패킷 손실, 폭탄·미사일·동적 맵의 실제 연동은 통과했다고 주장하지 않는다.
