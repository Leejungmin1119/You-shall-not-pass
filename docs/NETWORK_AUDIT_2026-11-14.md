# 네트워크 점검 · 2026-11-14

최신 main의 캐릭터 선택·애니메이션·이동 보간 변경과 로비 분리·호스트 강퇴 기능을 통합한 상태에서 점검했다.

## 수정한 오류

- 경기 중 들어오려다 거절된 외부 연결의 종료가 기존 경기의 참가자 이탈로 처리될 수 있었다. 실제로 좌석을 배정받았던 참가자가 나갔을 때만 경기를 중단하도록 수정했다.
- 미사일 조준 요청에는 라운드 번호가 없어, 늦게 도착한 이전 라운드 패킷이 현재 미사일을 조준할 수 있었다. 구매·사용 요청과 동일한 라운드·역할 검사를 적용했다.
- LAN 검색에서 방이 여러 개 발견되면 검색 상태가 끝나지 않았다. 15초 후 검색을 종료하고 호스트 IP 직접 참가 안내를 표시한다.
- 중계 서버에 인증 JSON으로 null이 들어오면 속성 접근 예외로 프로세스가 종료될 수 있었다. JSON 객체의 형태를 검사하고 해당 연결만 거절한다.
- 비밀번호 중계 방이 경기 시작 후 잠긴 상태로 남아, 로비로 복귀해도 새로운 참가자를 받을 수 없었다. 호스트만 방을 다시 열 수 있는 메시지와 로비 복귀 처리를 연결했다.

로비 병합 충돌은 메인 화면과 대기실 분리, 발판 이름표, 캐릭터 선택, 호스트 전용 × 버튼을 함께 유지하도록 해결했다. 강퇴는 현재 방에서의 연결 해제이며, 이후 재입장은 허용한다.

실제 네트워크 검사는 Mac 한 대에서 별도 프로세스의 호스트와 최대 3개 클라이언트를 실행했다. 자동화는 소유자의 Mirror Command와 서버 응답을 사용한다. 교대 후 모든 화면의 위치 일치도 검사했다. 로비 캡처에서 캐릭터 선택과 호스트 전용 강퇴 버튼의 배치를 확인했다.

종료 분기는 시험용 서버 동작으로 분리해서 검사했다. 사망 검사는 서버 사망 처리를 호출하고, 제한시간 검사는 종료 시각을 가깝게 설정하며, 점수 종료 검사는 승리 점수까지 지급한다. 이 조건은 명시적인 개발용 실행 인자에서만 활성화되는 probe의 명령이다. 게임의 기본 제한시간과 승리 점수 설정은 유지했다. 골인 접촉 검사도 공격자를 골인지점에 배치하는 서버 fixture를 사용한다. 복수 방 검색 검사는 발견 응답과 검색 경과시간을 주입한다.

## 검증 범위와 남은 제한

- Windows 실행과 Mac·Windows 간의 실제 통신은 별도 기기에서 확인해야 한다. 서로 다른 공유기, NAT, 방화벽, 패킷 손실 환경도 이번 실행 범위에 포함되지 않았다.
- 중계 서버는 로컬 WebSocket 검사까지 수행했다. 공개 서버 배포 및 Unity 클라이언트와 공개 중계 서버 사이의 연결은 확인하지 않았다. 기본 UI는 호스트 IP 접속을 사용한다.
- 이동은 기존 ClientToServer 구조다. 이번 수정은 이동 전체를 서버 물리 판정으로 전환하거나 위치 조작을 완전히 방지하는 작업을 포함하지 않는다.
- 경기 종료 검사는 종료 분기·점수·승자 동기화·로비 복귀를 검증한다. 사람이 정상 제한시간 전체를 플레이한 결과와 구분해야 한다.
- 빌드 경고가 남아 있다. 기존 인게임 TMP의 한글 닉네임 글꼴 표시 문제는 별도 UI 작업이다.

## 재실행

개발 빌드 실행 파일과 결과 폴더를 지정한다. Unity 검사는 같은 게임 포트를 사용하므로 순서대로 실행한다.

```sh
python3 Tools/Network/verify_lan.py --player "$PLAYER" --report-dir "$REPORT/lan"
python3 Tools/Network/verify_lobby_kick.py --player "$PLAYER" --report-dir "$REPORT/kick"
python3 Tools/Network/verify_network_edges.py --player "$PLAYER" --report-dir "$REPORT/edges"
```

중계 서버 검사는 `Server/PasswordRelay`에서 `node --test relay.test.mjs`로 실행한다.
