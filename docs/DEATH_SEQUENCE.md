# 피격 사망 연출

2026-11-09 적용. 씬 변경은 `Assets/Scenes/Stage1.unity`만 진행했다.

## 동작

- 서버에서 피격을 한 번 승인하면 `PlayerState`가 Dead가 된다.
- `RaceManager`는 함정 적중과 점수 처리가 끝난 다음 프레임에 DeathPresentation 상태로 들어간다.
- 전체 6초는 Mirror의 서버 시각을 기준으로 한다. 처음 0.1초 히트스톱은 첫 3초에 포함된다.
- 0.1초 뒤 0.2배로 시작해 3초 시점에 정상 속도로 복귀한다. 몸의 12프레임도 그 시점까지 완료된다.
- 하체 접촉 프레임부터 별 3개를 시계방향으로 연속 회전한다. 재생 속도가 복귀할 때 별 각도를 초기화하지 않는다.
- 나머지 3초는 마지막 몸 그림을 고정하고 별만 회전한다. 머리 흔들림은 없다.
- 6초가 끝나면 결과 UI 없이 교대한다. 기존 출발 위치·골드·보유 아이템·필드 함정 초기화를 사용한다.
- 피격 방향은 소유자가 전송한 시선 방향과 함정의 X 위치로 판정한다. 위에서 맞는 등 앞뒤가 모호한 경우 뒤로 쓰러진다.
- 사망 중 이동·구매·설치·추가 피격을 막고, 경기 잔여시간을 고정한다. 종료 시 실제 경과만큼 경기 종료 시각을 연장한다.
- 낙사는 `TryFall()`로 즉시 교대하며 6초 연출을 거치지 않는다. 무적 중 낙사도 기존처럼 적용한다.
- 승리 점수에 도달하는 결정타는 득점을 먼저 기록하고 6초 연출 뒤 기존 방의 로비로 복귀한다.

## 코드와 표시

- `DeathSequence`: 몸 Sprite·별·로컬 시간 배율·히트스톱 음소거의 표시 담당. 별도 NetworkBehaviour를 추가하지 않는다.
- `RaceManager`: 연출 시작 시각, 대상, 방향, 위치와 경기 시간의 서버 권한을 유지한다.
- `PlayerState`: 피격과 낙사의 원인을 구분하고 중복 사망을 막는다. 바라보는 방향은 변경될 때만 Command로 전달한다.
- 죽은 이동 본체와 충돌체는 멈추고, 표시용 몸만 캐릭터 폭만큼 밀린다. 다음 차례의 실제 위치 이동은 기존 ServerTeleport로 수행한다.
- fixed 함정은 통신 시계 자체를 바꾸지 않고 `SimulationTime`으로 히트스톱과 슬로모션을 반영한다.
- `MapViewController`: 사망 동안 표시용 몸을 추적하고 경계 제한을 임시 해제한다. 교대·씬 종료 시 원래 경계를 복구한다. Tab 전체 보기는 유지한다.
- 사망 줌: 히트스톱 직후 슬로모션과 함께 0.65초 동안 2.5배 확대한다. 서버의 실제 경과시간을 사용하므로 느려진 게임 시간 때문에 줌까지 지연되지 않는다.
- 슬로모션이 끝나는 3초 시점에도 확대 상태를 유지한다. 다음 공격자로 교대할 때 사망 전에 저장한 Lens 전체를 복구한다. 경기 종료·씬 종료·카메라 비활성화 시에도 복구한다.
- Stage1 > Main Camera > MapViewController > 사망 연출 줌에서 확대 배율과 줌인 시간을 조절할 수 있다. 전체 맵 카메라의 크기는 변경하지 않는다.
- `RaceTimerUI`: 사망 중 서버가 저장한 잔여시간을 표시한다.
- Stage1의 RaceManager > DeathSequence에서 인형·기사의 앞뒤 12프레임과 별 Sprite를 확인할 수 있다.
- 기존 `Body12_v2.png` 4장을 Sprite Editor 데이터 공급자 API로 잘라 연결했다. `30f_Sheet_v2` 미리보기는 런타임에서 사용하지 않는다.
- 피격음은 Stage1 > SoundPlayer > PlayerHit에서 설정한다. 전용 음원이 아직 없어 기존 `Stone_Impact_Smooth_Tail (1).mp3`를 임시 재사용한다.
- 히트스톱은 AudioListener.pause로 일반 음원을 멈추며, 피격음만 ignoreListenerPause로 재생한다. 종료·접속 해제 시 이전 상태를 복구한다.

## 검증

같은 PC의 Unity Editor 호스트와 Multiplayer Play Mode 원격 클라이언트 1개, 총 2개 실행으로 확인했다. 실제 PC 2대나 빌드 실행 검증은 아니다.

- 컴파일 성공. 최종 두 Editor Console의 오류 수는 각각 0. 기존 경고는 지우거나 억제하지 않았다.
- 인형의 정면·후면·위쪽 피격과 두 소유자에서의 교대를 확인했다. 연속 중복 사망은 거절됐다. 교대는 약 6.007~6.010초였다.
- 기사 모습으로 실제 RoundTrap 농구공 충돌을 두 방향에서 실행했다. 공의 초기 위치·속도만 테스트 코드로 지정하고 실제 충돌·적중·득점 경로를 사용했다. 두 수비자에게 각 1점이 지급됐고 약 6.03~6.05초에 교대했다.
- 양쪽 화면 모두 12프레임 전체가 표시됐다. 3초 이후 프레임은 11로 유지되고, 몸 위치는 고정되며 별은 3개였다. 안정 구간의 두 화면 몸 위치 차이는 측정상 0유닛이었다.
- 연출 중 잔여시간 변동은 0초였다. 두 화면에서 CanMove·CanUseTraps·CanHoldItem이 모두 false였다.
- 서버의 실제 구매·설치 함수도 연출 중 false를 반환했고 코스트는 변하지 않았다.
- 실제 낙사 구역으로 이동시켰을 때 약 0.036초 안에 교대됐으며 DeathPresentation을 거치지 않았다.
- 19점에서 실제 농구공 적중으로 20점이 됐을 때 약 6.01초에 경기 종료 상태로 넘어갔고, 두 연결을 유지한 채 로비로 복귀했다.
- 왼쪽을 바라보는 정면 피격에서도 뒤로 쓰러짐과 그림 반전이 적용됐다.
- 히트스톱 중 테스트 일반 음원의 timeSamples가 고정됐고 피격음은 재생 중이었다. 이후 음소거가 해제됐다.
- 연출 중 원격 클라이언트를 종료해도 양쪽 시간 배율 1, AudioListener.pause false로 복구됐다.
- 제한시간 1ms 전에 승인된 피격도 약 6.016초까지 연출된 뒤 시간 종료로 처리됐다.
- 화면 캡처에서 확인된 시작점의 사망 그림 잘림은 사망용 추적으로 보완한 뒤 양쪽 화면에서 다시 확인했다.
- 사망 줌을 추가한 뒤 두 실행에서 Lens와 실제 출력 카메라 크기가 8→3.2로 바뀌는 것을 확인했다. 3초 이후에도 3.2를 유지했고 공격자 교대 후 8로 복구됐다. 카메라 경계도 원래 활성 상태로 복원됐으며, 몸·별이 잘리지 않는 화면 캡처를 확인했다. 이 검증 중 오류는 두 실행 모두 없었다.
- 사망 줌의 씬 설정 중 LobbyScene과 Stage1을 에디터에서 잠시 함께 열 때 URP의 중복 Global Light 오류 1건이 Console에 남았다. 실행 중 예외 수집에서는 재발하지 않았고, 실제 Stage1 실행의 활성 Global Light는 각 실행당 1개였다. 기존 Console 기록은 삭제하지 않았다.

테스트 설정과 수치 변경은 런타임에만 적용했으며 씬·프리팹에 저장하지 않았다. 실행을 남기는 마지막 게임은 새 경기로 시작해 테스트 점수와 외형 변경이 남지 않게 한다.

## 사망 스프라이트 잘림 수정

- 원인: 생성된 원화의 일부 자세가 4×3 균등 칸을 넘어갔는데, 칸 안의 픽셀만 기준으로 Sprite Rect를 만들었다. 이 때문에 자기 머리·팔 일부가 잘리고 이웃 프레임 조각이 함께 표시됐다. 텍스처 반복 설정이나 네트워크 위치 문제가 아니었다.
- `Body12_v2.png` 4장의 불투명 연결 영역을 확인해 각 캐릭터 전체를 포함하도록 48개 Rect를 재설정했다. 겹치는 사각 영역에 들어오는 이웃 조각은 주 캐릭터의 윤곽만 사용한 Tight Mesh로 제외했다.
- Sprite Editor 데이터 공급자 API를 사용했고, 기존 이름·Sprite ID를 유지했다. 원본 PNG와 게임 코드, 씬은 이 수정에서 변경하지 않았다.
- 수정 전 8프레임에 이웃 그림의 주요 불투명 픽셀이 섞여 있었다. 수정 후 48프레임 모두 이웃 조각이 0개였고, 각 몸 전체가 포함되는 것을 픽셀·메시 비교로 확인했다.
- 호스트+MPPM 원격 클라이언트에서 인형 뒤/앞, 기사 뒤/앞의 4동작을 재생해 양쪽 모두 12프레임 전체가 적용되는 것을 확인했다. 화면 캡처에서 머리 잘림과 반대편 조각이 제거됐고 검증 중 런타임 오류는 없었다.

## 사망 연출 중 UI 숨김

- DeathSequence가 연출 시작 시 최상위 Canvas의 CanvasGroup 표시·클릭 상태를 보관한 뒤 숨긴다. UI 갱신과 네트워크 오브젝트는 계속 동작하며, 역할별 자식 패널 설정은 변경하지 않는다.
- CapstoneLobbyUI의 IMGUI 나가기 버튼과 알림도 같은 표시 상태를 따른다.
- 교대·연출 중단·씬 종료 시 기존 상태로 복구한다. 다음 공격자의 컨베이어·골드·인벤토리 표시는 기존 역할 규칙으로 결정한다.
- 솔로 Play Mode에서 연속 두 번 사망을 실행했다. 두 번 모두 연출 중 최상위 Canvas의 alpha=0, interactable=false, blocksRaycasts=false였고, 교대 후 alpha=1과 기존 클릭 상태로 복구됐다. 컴파일 실패와 검증 중 런타임 오류는 없었다. 이번 수정은 별도 멀티 실행 검증을 하지 않았다.
