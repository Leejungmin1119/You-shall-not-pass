# 비명·농구공·골인 효과음

## 적용

- 씬 변경: `Assets/Scenes/Stage1.unity`의 기존 SoundPlayer에 비명·농구공·골인 음원과 화살 발사·충돌·폭탄 폭발 음원을 등록했다.
- 농구공 프리팹: `Assets/Prefab/BouncingBall.prefab`의 RoundTrap > 바운스 사운드에서 Play Bounce Sound를 켰고 Min Sound Bounce Height는 0.1이다. 바위 프리팹은 소리를 켜지 않았다.
- 기존 돌 소리는 변경하지 않았다. 비명은 아래 무음 편집 기록에 따라 WAV로 교체했다.

## 비명

- DeathSequence가 피격 사망의 0.1초 히트스톱 직후 `DeathScream`을 한 번 재생한다. 낙사는 이 상태를 거치지 않으므로 비명이 없다.
- 비명은 화면의 슬로모션과 무관하게 기본 속도(pitch=1)로 재생한다.
- 단발 재생기는 공용 풀에서 예약한다. 비명이 먼저 끝나도 다른 효과음이 같은 채널을 재사용해 뒤늦은 속도 변경·정지의 영향을 받지 않게 한다. 사망 연출 종료·씬 종료에 예약을 반납한다.
- 기존 타격음(PlayerHit)은 그대로 두며 비명과는 별개의 소리다.

### 비명 앞 무음 편집

- 원본 `Wilhelm Scream sound.mp3`에서 약 0.88초의 앞 무음을 확인했다. 이 무음까지 슬로모션으로 재생되어 실제 비명이 늦게 들렸다.
- 파일 앞 0.875초를 잘라 `Assets/Sound/Wilhelm Scream sound.wav`로 저장했다. 시작 부분에 2ms의 짧은 페이드를 넣어 잘라낸 경계의 클릭을 방지했다. MP3 디코딩의 시작 지연이 붙지 않도록 WAV를 사용했다.
- 원본 백업: `C:/Users/User/AppData/Local/Temp/Wilhelm Scream sound.original.20261110_145827.mp3`.
- Unity AssetDatabase.MoveAsset으로 기존 GUID를 유지해 씬의 비명 연결을 보존했다. 편집본 길이는 약 1.96초이며 유효 파형은 파일 시작 약 0.0002초 이내에 나타난다.
- 무음을 건너뛰는 재생 오프셋 필드와 즉시 재생을 위한 임시 코드 변경은 모두 되돌렸다. 기존 0.1초 히트스톱 이후 한 번 재생하며, 이후 요청에 따라 비명은 기본 속도로 고정했다.

## 농구공

- RoundTrap의 실제 바닥 반사 직후 `max(velocity.y, 0)^2 / (2 * gravity)`로 다음 상승 높이를 추정한다.
- 첫 바운스 예상 높이를 공마다 저장한다. 예상 높이가 0.1 미만이면 무음, 첫 높이의 1/3 이하면 하, 1/2 이하면 중, 그보다 높으면 상이다.
- 바닥 방향 접촉에서 실제 반사가 발생할 때만 계산한다. 같은 물리 단계의 중복 소리는 막는다. 정지·구름·수직 벽 접촉은 바운스 소리를 발생시키지 않는다.
- 서버가 결정한 소리 종류와 위치만 ItemSoundMessage로 전원에게 신뢰성 전송한다. 기존 0.04초 이동 스냅샷과 분리했고 호스트도 동일한 수신 경로에서 한 번만 재생한다.
- SoundPlayer의 기존 거리 감쇠를 사용한다(최대 음량 5유닛, 무음 30유닛). 상·중·하 설정 음량은 각각 0.55/0.45/0.35, 공통 masterVolume은 기존 0.8이다.
- 예상 높이는 다른 지형에 다시 부딪히지 않는 자유 비행 기준이다.

## 골인

- RaceManager.TryFinish에서 유효한 골인을 승인한 뒤 ClientRpc로 GoalFireworks를 한 번 재생한다. 중복·이전 차례 요청은 기존 판정에서 거절된다.
- 일반 차례 교대에는 소리가 계속 재생된다. 승리 골인으로 경기 전체가 끝나 기존 정책대로 0.5초 뒤 로비 씬으로 바뀌면 씬의 SoundPlayer도 종료되므로, 4.73초 폭죽음의 뒷부분은 재생되지 않는다. 로비 전환 시간이나 오디오의 씬 유지 정책은 변경하지 않았다.

## 화살·폭탄

- 화살 생성 시 `arrow start sound.mp3`를 화살당 한 번 재생한다. 3발 묶음은 각 화살에서 한 번씩 발생한다.
- 지면에 처음 꽂히거나 서버가 플레이어 적중을 승인하면 `arrow hit sound.mp3`를 한 번 재생한다. 플레이어를 맞힌 뒤 지면에 닿거나 꽂힌 상태로 남아 있어도 같은 화살의 충돌음을 반복하지 않는다. 충돌하지 않고 사라진 화살에는 충돌음이 없다.
- Bomb.Explode가 최초 승인될 때 `Explosion sound.mp3`를 한 번 재생한다. 지면·플레이어 접촉 양쪽에 적용되며 원격 폭발 표시나 중복 호출은 추가 재생하지 않는다. 미사일에는 이번 폭발음을 연결하지 않았다.
- 기존 ItemSoundMessage를 재사용한다. ItemBase.SoundRequested를 공통 경로로 사용하도록 농구공 요청도 연결했으며, 서버만 요청하고 호스트와 원격은 수신 처리에서 각각 한 번 재생한다.
- 화살 충돌음과 폭탄 폭발음은 타격 순간의 효과음으로 히트스톱 중에도 재생한다. 일시 정지 중인 기존 채널을 빼앗지 않도록 공용 풀의 사용 상태도 보관한다.
- Stage1 > SoundPlayer > Sounds의 ArrowStart / ArrowHit / BombExplosion에서 음원과 음량을 조절한다. 설정 음량은 0.35 / 0.45 / 0.55이며 거리 감쇠는 기존과 같이 5~30유닛이다. 모두 기본 속도로 단발 재생한다. 음원 파일 자체는 변경하지 않았다.

### 화살·폭탄 검증

- 같은 PC의 Editor 호스트 + MPPM 클라이언트 1개로 실제 Spear/Bomb 생성·업데이트·충돌과 네트워크 전송 경로를 실행했다. 테스트용 생성 정보와 평지는 런타임에서만 제공했고 저장하지 않았다.
- 단일 화살, 3발 동시 화살, 지면 없는 화살, 플레이어 적중 화살을 실행했다. 서버 요청과 양쪽 재생 기록이 발사 6회·충돌 5회로 일치했다.
- 지면 폭발과 플레이어 접촉 폭발에서 양쪽 모두 폭발음이 총 2회였다. 지면 폭탄에 Explode를 다시 호출해도 추가 소리는 없었다.
- 농구공 회귀 검증에서 상·중·하가 양쪽 각각 한 번씩 재생됐다. 공통 전송 경로 변경으로 인한 중복은 없었다.
- 새 음원 모두 loop=false, pitch=1, 가까운 거리의 재생 음량이 0보다 큰 것을 확인했다. 비명도 기존 요청대로 pitch=1을 유지했다.
- 두 실행 모두 컴파일 실패와 검증 중 수집된 런타임 오류가 없었다. 최종 호스트 Console에는 별도의 Unity AI 도구 `connection.state_change` 연결 오류 1건이 남아 있었다. 스택이 Unity.AI.Tracing으로 이어지는 도구 연결 오류이므로 게임 사운드 범위에서 수정하지 않았다. 실제 PC 2대와 빌드 검증은 아니다.

## 검증

같은 PC의 Unity Editor 호스트 + Multiplayer Play Mode 클라이언트 1개(총 2개 실행)로 검증했다. 실제 PC 2대와 빌드는 검증하지 않았다.

- 두 실행 모두 컴파일 실패 없음, 테스트 중 수집한 런타임 오류 없음. 기존 Console 기록은 지우지 않았다.
- 실제 RoundTrap 낙하·반사 물리로 상 1회, 중 1회, 하 3회가 발생했다. 두 실행 모두 같은 순서와 횟수로 단발 재생했다. 서버가 요청한 횟수와 일치해 호스트 중복 재생도 없었다.
- 마지막 유효 바운스의 예상 높이는 약 0.119유닛이었다. 이후 더 작은 바운스와 정지에서는 소리가 없었다. 별도로 낮게 떨어뜨린 공과 바위에는 소리가 없었다.
- 청취 위치가 먼 경우 음량 0, 근처로 이동해 같은 실험을 반복한 경우 각 음원의 재생 음량이 양쪽에서 동일하고 0보다 큰 것을 확인했다.
- 경계값 검사: 높이 0.0999는 무음, 0.1은 재생. 비율 1/3은 하, 1/2은 중, 0.5001은 상이었다.
- 피격 사망 2회에 비명 시작이 각 실행당 정확히 2회였다. loop=false이고, 재생 중 pitch와 화면 Time.timeScale의 측정 차이는 0이었다. pitch는 약 0.2에서 1로 복귀했다.
- 실제 GoalZone.ServerTryContact 경로로 골인을 승인했다. 재전송한 이전 차례 요청은 false였고 폭죽 시작은 각 실행당 1회였다.
- TryFall이 승인된 낙사는 추가 비명 없이 즉시 교대했다.
- 테스트 지형·아이템 생성·위치 변경은 런타임에만 적용했고 씬에 저장하지 않았다.
- 편집 후 솔로 Play Mode 검증에서 피격 후 약 0.105초에 재생이 시작되고 약 0.117초에 유효 파형 구간으로 진행했다. loop=false, 기존 히트스톱·슬로모션 로직을 유지했으며 검증 중 런타임 오류와 컴파일 실패는 없었다.
