# 네 자리 로비 시험본 — 2026-11-04

브랜치: `codex/lobby-four-seats-prototype` / 기반: `03fb573`.
기존 작업 브랜치와 main을 수정하거나 병합하지 않고 별도 브랜치에서 시험한다.

## 동작

- 방 생성/참가 시 고정된 네 자리 중 빈 자리를 서버가 배정한다. 참가자가 나가도 다른 사람의 자리 번호는 바뀌지 않는다.
- 로비 캐릭터는 움직이지 않는다. 로비 위치 동기화 컴포넌트는 런타임에 비활성화하고 서버·클라이언트 모두 자리 위치로 고정한다. 게임 플레이어의 이동은 기존대로 유지한다.
- 머리 위에 READY/WAITING, 아래에 이름과 본인 표시를 배치한다. 빈자리에는 참가 대기 표시가 나온다.
- 2~4명 중 입장한 전원이 READY이면 서버 시각 기준 5초 카운트다운을 자동 시작한다.
- `게임을 시작합니다`와 남은 초를 표시한다. F 또는 Cancel ready로 언제든 준비를 취소할 수 있다.
- 준비 해제·이름 변경·입장·퇴장은 기존 카운트다운을 취소한다. 조건을 다시 만족하면 새 5초를 센다. Mirror 기본 동작에 따라 퇴장 시 남은 참가자들의 준비도 해제된다.
- Enter나 이전 수동 시작 호출로 카운트다운을 건너뛸 수 없다. 종료 직전에도 서버가 현재 참가자와 준비 상태를 다시 검사한다.
- 시작 시각은 각 방 플레이어의 SyncVar로 전달한다. 클라이언트가 자체 타이머로 게임 시작을 결정하지 않는다.
- 기존 SOLO TEST (DEV)는 별도 개발자 시험 기능으로 유지한다.

## 직접 시험

1. 이 브랜치에서 Unity의 LobbyScene을 Play한다.
2. Create room으로 방을 만들고 다른 실행 창/기기에서 참가한다.
3. 2명 이상에서 F 또는 Ready up으로 전원 준비한다.
4. 5초 이내 한 명이 준비를 해제하면 대기 상태로 복귀하는지 확인한다.
5. 다시 준비하면 5초 전체를 센 뒤 게임으로 전환되는지 확인한다.

## 검증 결과

- Unity 6000.3.24f1 개발 빌드 성공. C# 컴파일과 Mirror Weaver를 포함한다.
- 실제 KCP loopback Host와 별도 클라이언트 프로세스 최대 3개로 28개 검사를 통과했다.
- 1인 자동 시작 차단, 두 자리의 고유 배정, 위치 변경 시도 뒤 고정 위치 복구, 모든 화면의 동일 시작 시각.
- 수동 시작 우회 차단, 준비 취소 후 이전 시각에 시작되지 않음, 재준비 시 새 5초, 이름 변경 취소.
- 2인 및 4인에서 서버 마감 시각 이후 게임 씬 전환, 로비 복귀 후 준비·카운트다운 초기화.
- 카운트다운 도중 입·퇴장 취소, 네 자리 동시 배정, 중간 자리 퇴장 뒤 다른 자리 유지, 재입장 시 빈자리 재사용.
- 네 프로세스 모두 검사 중 런타임 오류가 기록되지 않았다.
- 화면 검수에서는 한국어 안내 표시와 동적 글꼴 로딩을 추가 확인했다. OS에 설치된 글꼴만 선택하고 IMGUI의 공유 임시 GUIContent 대신 캐시된 GUIContent를 사용한다.

이 검사는 같은 Mac의 loopback 통합 검사다. 서로 다른 기기, Wi-Fi 검색 복귀, 인터넷 중계와 패킷 손실 환경을 새로 검증했다는 뜻은 아니다.

## 시험 도구

`Tools/Lobby Prototype/Build Development Test Player`는 개발 빌드를 프로젝트의 `Builds/LobbyPrototypeTests/lobby-prototype.app`에 만든다(macOS용). 결과 JSON도 같은 폴더에 저장된다.

개발 빌드는 `-lobbyProbeDirectory <절대 경로> -lobbyProbeId host|c1|c2|c3` 인자가 있을 때만 상태 기록·제어 시험 도구를 켠다. Host에는 `-lobbyProbeHost`를 추가한다. 일반 실행에서는 켜지지 않고 출시 빌드에서는 제외된다.
`<id>.command.json`의 `sequence`를 증가시키며 `ready`, `rename`, `nudge`, `tryStart`, `return`, `leave`를 시험할 수 있다. `ready`에는 bool `ready`, `rename`에는 `name`을 추가한다. 상태는 `<id>.json`, 씬/카운트다운 이벤트는 `<id>.events.jsonl`에 기록된다.

출시용 로비와 일괄 교체하기 전 팀 검토를 위한 예비 구현이다.
