# 네트워크 성능 개선 · 2026-11-15

기준 커밋은 `afdcbed`다. 같은 Mac에서 별도 KCP 호스트 1개와 클라이언트 3개를 실행하고 전후를 비교했다. 이동 sendRate, KCP Interval, 충돌 검사 주기와 게임 규칙은 기존 설정을 사용한다.

## 코드 변경

- 서버에서 실제 `PlayerState`만 등록·해제하는 목록을 사용한다. 함정 적중, 골인·낙사와 무적 영역 검사는 맵 오브젝트 전체 대신 이 목록을 확인한다. 등록은 `OnStartServer`, 해제는 `OnStopServer`에서 처리하며, Domain Reload를 끈 재실행도 초기화한다. 비역할 시험 씬의 여러 플레이어 판정도 유지한다.
- 미사일은 마지막으로 보낸 월드 조준점과 비교한다. 0.01유닛 이상 바뀌면 기존 최대 20Hz 주기로 보내고, 같은 좌표는 0.25초마다 재전송한다. 작은 이동도 마지막 전송 좌표에서 누적된다. 활성 미사일 변경, 새 사용 성공, 라운드·보유 상태 초기화 시 첫 조준을 다시 보낸다. 서버의 라운드·역할·좌표 검사는 유지한다.
- 공·바위는 마지막 전송 위치 0.01유닛, 회전 0.5도 기준으로 변화 여부를 확인한다. 움직이는 상태의 최대 전송 주기는 0.04초이며, 거의 멈춘 상태는 0.25초마다 다시 보낸다. 시간 기준은 기존 물리 시계다. 소멸 메시지는 Reliable을 사용한다.
- 로비 참가자 목록은 매 IMGUI 이벤트의 LINQ 배열 생성 대신 프레임당 한 번 갱신하는 리스트를 재사용한다. 좌석·준비 상태 조회의 캡처 람다도 제거했다. 화면 전환에서 캐시를 비운다.

## 측정 결과

CPU 값은 해당 코드 구간을 1만 회 호출한 5개 표본의 중앙값이다. 충돌 벤치마크는 실제 참가자 4명의 같은 접촉 검사를 반복한다. 추가 오브젝트는 물리·게임 로직이 없는 시험용 NetworkIdentity이며, 실제 함정 256개의 프레임 성능으로 해석하면 안 된다.

| 코드 구간 | 이전 | 이후 | 시간 감소 |
| --- | --- | --- | --- |
| 로비 목록 조회 · 호스트 · 같은 프레임 캐시 | 18.66 ms | 0.16 ms | 99.1% |
| 로비 목록 조회 · 클라이언트 · 같은 프레임 캐시 | 21.44 ms | 0.24 ms | 98.9% |
| 적중 판정 · 실제 씬 | 23.44 ms | 8.78 ms | 62.5% |
| 적중 판정 · 비플레이어 64개 추가 | 66.29 ms | 8.94 ms | 86.5% |
| 적중 판정 · 비플레이어 256개 추가 | 206.07 ms | 8.31 ms | 96.0% |

로비 표는 이미 갱신된 같은 프레임의 목록 조회 비용을 측정한다. 매 프레임 최초 갱신과 로비 렌더링 전체의 비용을 포함하지 않는다. 접촉 검사 결과는 전후 모두 1만 회 동일하게 적중했다. 이 수치는 코드 구간의 측정이며 전체 게임 FPS·인터넷 지연 개선율을 의미하지 않는다.

관리 메모리 수치는 비교에서 제외했다. 이 런타임의 `GC.GetAllocatedBytesForCurrentThread()`는 의도적으로 4KB 배열을 할당해도 증가하지 않았다. 최종 측정기는 미지원 상태를 명시하고 할당량을 -1로 기록한다. 기준 표본의 0 역시 실제 무할당으로 해석하지 않는다. 로비 임시 배열 제거는 코드 변경으로 확인했다.

전송량은 `NetworkDiagnostics.OutMessageEvent`로 셌다. 아래 횟수는 4초 동안의 메시지 송신 연산 수이며 KCP·UDP 헤더는 제외한다. 공·바위 메시지의 수신 대상에는 호스트 로컬 연결도 포함된다. 계측 구독은 전송 측정 구간에만 활성화한다.

| 전송 상황 | 이전 횟수 | 이후 횟수 | 초당 횟수 감소 |
| --- | --- | --- | --- |
| 고정 조준 · 4초 | 80 | 16 | 80.0% |
| 이동 조준 · 4초 | 80 | 76 | 5.3% |
| 정지 바위 · 4초 | 100 | 16 | 83.9% |
| 이동·착지 바위 · 약 1초 | 19 | 15 | 21.4% |

이동 조준은 정해진 화면 좌표를 연속 변화시키는 시험이다. 바위 이동 구간에는 낙하·반사·착지가 포함된다. 변화가 미세한 구간은 생략되므로 실제 횟수도 일부 줄었다. 최대 이동 전송 주기는 유지한다. 소멸 검사에서 Reliable Expired 메시지는 전후 모두 정확히 한 번 발생했다.

고정 조준 상태에서 시험용 서버 미사일의 조준점을 일부러 잘못 설정한 뒤, 소유자의 같은 좌표 재전송으로 0.193초 안에 복구되는 것을 확인했다. 이는 서버 상태 복구 fixture이며 실제 UDP 패킷을 버리는 네트워크 손실 시험과 구분한다.

## 동작 검증

- 기존 실제 KCP 4인 검사 76개 통과. 구매·사용·교대·점수·위치 일치·재접속·솔로 진입과 복귀를 포함한다.
- 강퇴 검사 17개 통과. 권한, 안내, 카운트다운 취소, 자리 재사용과 응답하지 않는 참가자를 검사한다.
- 네트워크 경계 조건 20개 통과. 캐릭터 선택, 늦은 참가 거절, 이전 라운드 조준 거절, 사망 중 이탈과 경기 종료·승자를 검사한다.
- Node.js 중계 검사 8개 통과.
- 모든 snapshot 읽기에서 서버 플레이어 목록을 실제 spawn 사전의 PlayerState와 독립적으로 비교했다. 중복·누락 없이 일치했고 로비 복귀·서버 종료 시 비었다.
- Mac·Windows 개발 빌드 성공. 오류 0건이며 경고는 각각 347건·512건이다.

합계 121개 동작 검사가 통과했다. CPU 비교 5개 조건과 전송량 비교·조준 복구 검사도 통과했다. 시험 프로세스가 수집한 런타임 오류는 0건이다. 경기 종료 분기의 시험용 조건 등 기존 fixture의 범위는 `NETWORK_AUDIT_2026-11-14.md`에 설명돼 있다.

## 재실행과 범위

두 계측 컴포넌트는 Editor/Development Build에만 포함되며 명시적인 실행 인자에서만 활성화된다. 실제 게임 설정이나 씬에 컴포넌트를 추가하지 않는다. 동일 포트를 사용하므로 검사 도구는 순서대로 실행한다.

```sh
python3 Tools/Network/measure_cpu.py --player "$BASE_PLAYER" --report-dir "$REPORT/base-cpu"
python3 Tools/Network/measure_traffic.py --player "$BASE_PLAYER" --report-dir "$REPORT/base-traffic"
python3 Tools/Network/measure_cpu.py --player "$NEW_PLAYER" --report-dir "$REPORT/new-cpu" --baseline "$REPORT/base-cpu/result.json"
python3 Tools/Network/measure_traffic.py --player "$NEW_PLAYER" --report-dir "$REPORT/new-traffic" --baseline "$REPORT/base-traffic/result.json"
```

CPU 계측은 동기식 함수 루프 안에서 시계와 카운터를 읽는다. LobbyPrototypeProbe의 JSON·파일 작업이나 진단 이벤트를 이 구간에 포함하지 않는다. 전송량 시험은 정해진 수명·위치의 fixture를 사용한다. 자세한 원본 표본과 비교 값은 `validation/network-performance-2026-11-15.json`에 기록했다.

Windows 실제 실행, 서로 다른 PC·공유기, 실제 지연·패킷 손실 환경과 공개 중계 서버의 성능은 추가 검증 범위다. 이번 작업은 기존 클라이언트 이동 계산·호스트 판정 구조를 사용한다.
