# 메인 로비와 방 대기실 분리 — 2026-11-07

브랜치 `codex/lobby-main-room-split`, 기반 `009fc83`. 기존 시험 브랜치와 main에 병합하지 않고 구현했다.

## 화면과 흐름

### 메인 로비

선택한 B안의 하늘·초원·발판 배경을 사용한다. 그림에 버튼/텍스트를 굽지 않고 실제 UI를 그린다. 캐릭터는 게임의 대기 스프라이트를 재생한다.

- **방 만들기**: KCP Host를 시작하고 같은 프로세스의 방 대기실로 들어간다.
- **호스트 IP + 참가**: 지정한 IPv4로 접속한 뒤 같은 방 대기실로 들어간다.
- **테스트 게임 실행**: 기존 비공개 1인 시험 모드로 게임을 바로 실행한다. 접속을 받거나 방을 광고하지 않으며, 로딩 중에도 대기실을 표시하지 않는다. 이번 시험용 UI에서는 일반 빌드에서도 버튼을 표시한다.
- **내 IP 보기**: 현재 IPv4 확인·복사·새로고침을 유지한다.

이 화면에 이름 입력·네 자리·READY를 표시하지 않는다. 자동 방 검색, 인터넷/비밀번호 메뉴도 노출하지 않는다. 기존 중계/검색 백엔드 코드는 제거하지 않았다.

### 방 대기실

연결된 로컬 RoomPlayer가 있을 때 표시한다. 기존 서버 좌석 번호와 인게임 캐릭터로 네 자리를 그린다.

- 소유자의 이름 입력/저장, 머리 위 이름과 READY/준비 중.
- F 또는 준비 버튼, 2~4명 전원 준비 시 서버 시각 기준 5초 후 시작.
- 준비 해제·이름 변경·입퇴장 시 카운트다운 취소.
- 방장 IP 확인과 방 나가기.

경기 종료로 연결을 유지한 채 복귀하면 이 대기실로 돌아온다. 방을 나가거나 Host 연결이 끊기면 메인 로비로 돌아온다. 혼자 시험을 끝낸 경우도 메인 로비로 돌아온다.

## 구현

`CapstoneLobbyUI`의 Main/Room/Game 표시를 실제 연결·씬·RoomPlayer 상태에서 결정한다. 수동 화면 플래그와 연결 상태가 따로 어긋나지 않도록 했다. 16:9 기준 UI를 화면에 맞춰 배치해 창 비율이 달라도 조작 요소가 늘어나거나 잘리지 않게 한다. 게임 중에는 로비 배경을 그리지 않는다.

기존 Mirror 방 관리자, 구매·함정 판정과 READY 서버 로직을 변경하지 않았다. 씬의 배경 텍스처 참조와 임포트 설정은 Unity Editor API로 저장했다. 배경 에셋은 `Assets/MyGame/Art/Lobby/MainLobbyWorld.png`이며, 선택한 B안 생성 시안에서 글자·컨트롤·캐릭터를 제거해 만든 배경이다.

## 검증

- Unity 6000.3.24f1에서 Mac·Windows Development 빌드 성공, 오류 0. 패키지 셰이더 등 빌드 경고는 남아 있다.
- **75개 실제 프로세스 통합 검사 통과**, Host+Client 3개의 기록된 런타임 오류 0.
- 초기 메인 화면, Host/참가 후 대기실, 게임 시작/종료 복귀, Host 종료 시 메인 복귀.
- 고정 좌석·이름·READY 취소/재준비·서버 5초·이전 턴 거절·소유자 인벤토리·원격 구매/사용·점수/교대·이탈/검색·직접 접속 실패 복구의 기존 회귀 검사.
- 혼자 시험은 대기실을 노출하지 않고 게임으로 이동하며, 종료 후 오프라인 메인으로 복귀.
- 실제 그래픽 Player에서 메인, 내 IP 패널, 이름과 READY가 있는 4인 대기실, 카운트다운, 게임 화면을 캡처해 배치 확인. 게임 화면에 메인 배경이 덮이지 않는 것도 확인했다.

## 재현

현재 소스로 Development Player를 빌드한 뒤 전용 빈 결과 폴더를 사용한다. Python 표준 라이브러리만 필요하다.

```sh
python3 Tools/Network/verify_lan.py \
  --player '/absolute/path/SplitLobby.app/Contents/MacOS/넌 못지나간다' \
  --report-dir '/absolute/path/temporary-lobby-results'
```

개발용 probe는 `-lobbyProbeDirectory`와 `-lobbyProbeId`를 명시할 때만 생성된다. `-lobbyProbeManual`은 자동 접속을 중단해 초기 메인을 확인하기 위한 옵션이다. 제어 파일의 `capture`는 현재 게임 프레임을 지정된 시험 폴더에 저장하고 `showIp`는 실제 UI의 IP 패널 동작을 호출한다. 이 도구는 일반 실행과 비개발 빌드에서는 동작하지 않는다.

골인 검사는 서버 위치 배치 fixture를 사용하며 사람이 달려서 골인한 실기 검사와 구분한다. 실제 Windows 실행, Mac↔Windows 다중 기기 및 다른 라우터 대역 연결, 지연·손실·인터넷 중계는 이번 검사 범위가 아니다.

## 이름표 위치 조정

방 대기실의 개인 이름표를 발판 흙 부분의 중상단에 배치했다. 캐릭터는 가리지 않고, 가독성을 위한 옅은 배경과 함께 본인 표시도 발판 안에 배치했다. 머리 위 READY는 유지한다. Mac 실제 4인 화면으로 배치를 확인하고 Mac·Windows 개발 빌드를 갱신했다. 네트워크 판정·메시지는 변경하지 않았다.
