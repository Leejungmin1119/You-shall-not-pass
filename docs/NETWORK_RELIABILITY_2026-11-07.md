## 변경

- **IPv4 직접 참가**: 로비 하단에 방장 IP 입력과 참가 버튼. 자동 LAN 검색을 사용할 수 없는 환경에서 도달 가능한 Host 주소로 KCP 접속한다. 잘못된 형식·URL·포트·미지정/멀티캐스트/전체 브로드캐스트 주소는 거절한다.
- **LAN 안내와 Host 주소**: 유선/Wi-Fi 모두 같은 내부망에서 사용할 수 있다고 표시하고, 방장에게 현재 IPv4 주소를 보여준다.
- **실패 복구**: 접속 성립을 최대 12초 기다린 뒤 정리한다. 연결 실패·방장 종료 안내를 표시하며 직접 참가 영역에는 마지막 실패 이유를 유지한다. 정상 나가기에는 실패 안내를 띄우지 않고, 다음 시도에서는 이전 오류를 비운다.
- **로비 재광고**: 경기 중에는 UDP 검색 응답을 중단하고 로비로 돌아오면 다시 광고한다. 처음 방을 열 때 중복으로 광고를 시작하지 않는다.
- **이탈 정책 일치**: 현재 정책을 유지한다. 경기 준비 연출과 플레이 도중 참가자가 이탈하면 판을 승자 없이 종료하고 남은 참가자를 로비로 돌린다. 방 기반 경기에서 별도 공격자 승계 경로가 동시에 실행되지 않는다.
- **검증 도구**: 개발 빌드 전용 probe에 검색/직접 접속/실제 구매·사용/골인 fixture 관찰을 추가했다. 일반 실행에서는 opt-in 실행 인자가 없으면 켜지지 않는다.

UI는 기존 IMGUI 로비를 유지한다. 화면 검수에서 기존 하단 안내와 IP 입력란의 겹침을 수정했다.

고정 좌석·2/4인 자동 시작·준비 취소·재준비·이름 변경·입퇴장 취소·수동 시작 우회 방지·로비 복귀와 좌석 재사용을 확인했다.

최신 Stage1에서 원격 Client의 실제 Command로 구매와 함정 사용을 요청했다. 소유자 슬롯, 공개 보유 개수, 실패 시 미소모, 네 화면의 함정 생성 관찰과 공수 교대 후 초기화를 확인했다.

골인은 서버의 위치/턴 검사를 확인하기 위해 명시적인 fixture로 공격자를 골인 영역에 배치했다. 이전 턴 및 영역 밖 요청은 거절하고, 영역 접촉 후 점수 1점과 다음 공격자/턴이 전원에게 같은 값으로 복제되는 것을 확인했다. 사람이 달려서 골인한 실기 검사로 표현하지 않는다.

## 재현

Development Build를 만든 뒤 전용 빈 결과 폴더로 다음을 실행한다. Python 표준 라이브러리만 사용한다. 프로세스 Host 하나와 Client 최대 세 개를 생성하고 종료한다.

```sh
python3 Tools/Network/verify_lan.py \
  --player '/absolute/path/NetworkTest.app/Contents/MacOS/넌 못지나간다' \
  --report-dir '/absolute/path/temporary-network-results'
```

검사 목록과 빌드 요약은 [검증 기록](validation/network-reliability-2026-11-07.json)에 있다. `LobbyPrototypeProbe`와 fixture는 Editor/Development에만 포함되며, 명시적인 probe 실행 인자가 없으면 생성되지 않는다.

## 현재 집 환경에서 시도하는 방법

Windows에서 새 빌드로 LAN 방을 생성한 뒤, 맥의 같은 버전에서 하단 IP 입력란에 Windows Host IPv4를 입력한다. 앞서 알려 준 주소가 아직 유효하면 `192.168.55.80`이다. 현재 주소는 Windows 방 화면에 표시되는 값을 따른다.

직접 접속은 검색용 브로드캐스트를 거치지 않는다. 공유기 라우팅/NAT/방화벽 때문에 IP 사이의 통신 자체가 차단된 경우에는 연결되지 않을 수 있다. 인터넷 중계나 NAT 자동 우회가 구현되었다는 뜻은 아니다.
