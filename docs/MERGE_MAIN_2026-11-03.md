# main 병합 기록 - 2026-11-03

- 대상 브랜치: `codex/you-shall-not-pass-work`

- 가져온 main: `858ceeb`

`main`에는 새 레이스 상태 관리, 3칸 인벤토리와 HUD, 폭탄·미사일·창 등의 공통 아이템 처리, 플레이어 애니메이션과 배경·지형이 추가되어 있었다. 두 레이스 관리자를 같은 씬에서 실행하지 않도록 `main`의 씬·프리팹 연결과 `RaceManager`, `PlayerInventory`, `PlayerHeldItem`, `SpearNetwork`를 실행 경로로 선택했다.

이전 `RaceSession`, `NetworkRaceInventory`, `RaceTrapService`, `RaceNetworkRules` 및 해당 전용 설정 에셋은 중복되므로 제거했다. 원래 구현은 병합 이전 커밋에서 확인할 수 있다. 새 씬·플레이어 프리팹은 main 버전을 사용했고 YAML에 식별자를 수동으로 합치지 않았다.

## 기존 브랜치에서 이식한 동작

- 구매·선택·사용 요청의 라운드 번호를 검증하여 이전 라운드 요청을 거절한다.
- 골인·낙사 요청은 서버가 보유한 콜라이더 위치로 다시 확인한다. 알림과 이동 스냅샷의 도착 순서에 대비한 서버 접촉 검사도 유지한다.
- 구매 쿨타임은 시험 기본값 0.25초로 유지한다. 아이템 내용·선택 슬롯·손에 든 아이템은 소유자만 수신하고, 공개 개수는 `PlayerState.InventoryCount`에 보낸다.
- 복귀 무적 종료 시각을 동기화하고 보호된 플레이어 주변 1.5유닛의 사용 요청을 거절한다. 이 반경은 기존 시험 기본값이다.
- 경기 전체 종료 시각을 라운드마다 초기화하지 않는다. 골인 후 20초 마감도 전체 경기 종료 시각을 넘지 않는다.
- 점수 종료·시간 종료·참가자 이탈 사유와 공동 승자 ID를 동기화한다. 기존 main의 로비 복귀 동작은 결과 복제를 위해 0.5초 대기 후 실행한다.
- 골인 후에는 이동은 잠그고 아이템 요청은 허용한다. 연습용 피해·무료 폭탄 단축키는 실제 레이스에서 서버 측도 차단한다.

main의 맵 소개 6초, 카메라 복귀 1.5초, 3·2·1 각 1초와 라운드별 인벤토리·코스트 초기화 정책은 유지했다. 이를 10월 16일의 별도 설정 에셋 값으로 덮어쓰지 않았다. 라운드마다 코스트/인벤토리를 유지할지 여부 등 기획 차이는 팀 합의가 필요하다.

## 검증과 한계

- Unity 6000.3.24f1에 포함된 Roslyn 컴파일러와 이 프로젝트의 참조 목록으로 게임 코드와 편집기 코드를 컴파일했다. 로그와 출력은 저장소 밖 작업 폴더에 보관한다.
- 씬·프리팹의 스크립트 GUID와 활성 빌드 씬 경로를 검사했다. 충돌 마커와 중복 `RacePhase` 정의도 검사한다.
- Unity batch 검증은 실행을 시도했지만 `No valid Unity Editor license found`로 중단됐다. 따라서 이번 병합본의 Play 실행, Mirror 후처리, 실제 Host/Client 동작을 검증했다고 주장하지 않는다.
- 10월 16일의 36개 검사와 4인 실행 기록은 이전 구현에 대한 기록이다. 새 병합본의 통과 결과로 재사용하지 않는다.

라이선스 복구 후 `RaceNetworkSetup.Validate()`로 연결을 검사하고, LobbyScene에서 Host와 별도 Client를 실행한 뒤 `RaceNetworkChecks.Run()`을 사용한다. 이 검사는 런타임 상태를 바꾸므로 별도 시험 Play 세션에서 실행하고 종료한다. 개발 빌드의 `-raceSmokeReport` / `-raceSmokeActions` 도구도 새 API에 맞게 갱신했다.
